1. TEST FLOW LENGKAP
════════════════════════════

Pastikan skenario ini berjalan dari ujung ke ujung:

SKENARIO A — Sales → Gudang → Driver:
1. Sales login di localhost:3002
2. Sales buat Sales Order (SO) baru
3. Admin di localhost:3000 approve SO
4. Gudang login di localhost:3003
5. Gudang lihat SO muncul di /outbound
6. Gudang proses picking + konfirmasi kirim
7. Driver login di localhost:3005
8. Driver lihat tugas pengiriman baru di /deliveries
9. Driver update status: berangkat → tiba → selesai
10. Admin di localhost:3000 lihat status "delivered" di monitoring

SKENARIO B — Pembelian → Gudang:
1. Admin buat Purchase Order di localhost:3000
2. Gudang lihat PO muncul di /inbound
3. Gudang proses penerimaan barang
4. Stok otomatis update, admin bisa lihat di inventory

SKENARIO C — POS → Finance:
1. Kasir login di localhost:3004
2. Kasir buat transaksi penjualan
3. Admin lihat transaksi di /monitoring/pos
4. Otomatis terbuat jurnal akuntansi di backend

════════════════════════════
2. SHARED PACKAGES (OPSIONAL)
════════════════════════════

Jika ada kode yang duplikat di semua app, pindahkan ke:
packages/
├── ui/          → komponen shared (Button, Input, Badge, dll)
├── auth/        → logic JWT, useAuthStore, api.ts
└── types/       → TypeScript interfaces shared

Update import di semua app untuk pakai packages/*.
Ini opsional, kerjakan hanya jika ada duplikasi signifikan.

════════════════════════════
3. ENVIRONMENT PRODUCTION
════════════════════════════

Buat .env.example untuk semua app dengan variabel:
- NEXT_PUBLIC_API_URL     → URL backend
- NEXT_PUBLIC_APP_NAME   → nama app (untuk title browser)
- NEXT_PUBLIC_ADMIN_URL  → URL admin panel (untuk deep link)

Buat docker-compose.yml di root:
services:
  backend:   port 4000
  frontend:  port 3000 (admin)
  sales-app: port 3002
  gudang-app:port 3003
  pos-app:   port 3004
  driver-app:port 3005
  postgres:  port 5432
